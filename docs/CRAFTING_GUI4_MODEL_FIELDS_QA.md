# GUI4模型残差：顶点与UV定位

继续检查[GUI4建筑保留场景](CRAFTING_GUI4_HOLDOUT_QA.md)的1,419点残差。本轮是CPU字段诊断，没有重新绘制产品或改变默认模型，不能记成一次新的像素修复。

从已保存并独立资格确认的GUI4 C++导出，仅重建配方scissor内G94的IB／VB和两个256字节CBV。实际输入为16字节顶点：binary16位置、UNORM16 UV与RGBA8颜色，234个索引组成39个quad。通过原始heap放置范围、UI前CopyBufferRegion及稀疏upload页恢复实际字节；选中范围共3,476字节。XPRESS压缩块不能随机解压，CPU共解压36,577,280字节，仅解释选中范围，未解析其他绘制／纹理payload或运行PIX／GPU重放。

另一边直接执行上一轮冻结的普通模型构造与当前`layoutGuiModel`，保留相同原图集、相机和居中公式。配方归属来自公开源布局；最小几何匹配仅关联诊断面，不向生产传入捕获顶点、矩阵或修补值。39面都对应同样顶点顺序与三角形索引。

地毯的两个顶面角同时被侧面引用，共四处Y字段：产品为144.375，原生为144.5，相差0.125游戏像素；GUI4下相当于0.5物理像素。X、UV、面颜色与索引一致，原生draw为POINT／CLAMP采样。这里已存在进入shader之前的几何失配，不能把273个地毯残差仅归因于纹理采样。未执行仅替换这些顶点的GPU反事实，不宣称这四处字段已解释全部273点。

三个阶梯分别只有一个Y分量差−0.0625，玻璃板同时存在形状及UV失配。它们不能统称为同一个sampler问题，也不支持修改纹理或亮度。五个半砖／完整方块单元的全部字段一致，与上轮这些单元完整RGBA0相符；这仍不是全模型或整页认证。

## 排除直接量化修补

对几何可对应的九个非玻璃板模型，以Python独立IEEE binary16编码重算144个顶点的XY，全部与当前公共打包输出相同。当前实现按其已声明投影得到的半精度值并未算错；它与原生的输入变换规则仍有差异。

仅把现有公式改成逐步float32运算，仍保留三个阶梯的各一处和地毯四处Y差异。此前冻结的三个Y偏移代表值`8.936157698051645`、`8.943092037388354`和`8.9375`也都未通过地毯四处Y。没有搜索新的偏移、修改half舍入规则、加epsilon或选取拟合常数。

固定旧角度／比例后，新约束仍给出一个非零宽度的可行区间，并非唯一相机；它不能证明正常引擎变换、原点计算或运算顺序。下一步需要独立的变换来源，不能将捕获坐标转成每个物品的补偿表。
