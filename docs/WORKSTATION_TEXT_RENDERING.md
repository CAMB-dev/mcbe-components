# 工作站文字：原点与渲染顺序

2026-10-30。本研究比较现有路径，保留当前默认行为，不新增字体 provider、公共 API 或组件。提高 BitmapText 的 backing 分辨率并没有统一改善原生差异，因此不将实验 B1 设为默认。

## 原点与基线分别说明什么

原始 UI JSON 决定锚点和文字盒，glyph bearing 决定盒内墨迹。七个已捕获画面的 77 次文字 draw，能由一个相同候选规则解释其实际投影：完成源布局与显式 paintOffset 后，用 float32 将全局游戏坐标乘 GUI scale，再向下取整到物理像素。这覆盖铁砧、砂轮、附魔台与附魔台 GUI4 保留场景；它不是唯一原版 CPU 算法的证明，也不能直接用已量化的 DOMRect 取整替代。

实际 Chromium 基线探针测得：当前祖先缩放 2.5 时，标题、物品栏、名称和费用的基线都位于各自宿主顶部下方 45 个物理像素，即 18 CSS px。名称 normal 子行与标签 20 px 行具有相同基线距离；墨迹顶部差异不能单独证明它们使用不同基线。

但探针的整帧无扰动认证失败：插入零尺寸 baseline span 时画面未变，移除后两次运行均改变结果钻石中的 94 个像素，alpha 未变。图片 DOMRect 不变，无操作重复截图稳定；重绘相位变化的原因未确定。该失败原样保留，不能当作字体修复或整帧一致性通过。

## 比较路径与覆盖

六个固定原生 UI target：铁砧 QA / Long / Empty / Invalid、砂轮不兼容输入、附魔台 GUI5 默认书本。各组沿用相同场景数据与物品材质；普通 CSS 的三种字体配置分别记录，B0 / B1 / C 复用相同的原始字体页。

| 组 | 路径 |
| --- | --- |
| P-open18 / P-local20 / P-classic20 | 当前普通 CSS 控件，分别使用三种字体配置 |
| B0 | 已有 `renderText` 返回共享 WebGL `BitmapText`，局部光栅后交给祖先缩放 |
| B1 | 同样字体、metrics、advance 与字格，以更高 backing 分辨率光栅，再逆缩放回同一个逻辑盒 |
| C | 已有完整 `imageRender.text` 源 profile，连同源面板和物品路径 |

铁砧 B0 / B1 只替换标题与物品栏标签，名称和费用仍为当前 DOM；砂轮替换两类标签；附魔台另覆盖三个费用数字，符文节点保持原样。DPR1 下，B1 的 15 个实际 canvas 都测得一 backing 像素对应一帧缓冲物理像素，但没有加入原生全局 snapping。C 是完整源合成正控，不能把其全部改善归因于文字。

## 完整画面结果

下表为相对原生 target 的差异 RGBA 像素数，每张完整画面为 2570 × 1402（3,603,140 像素），没有遮罩、容差或截图拟合。三种 P 的全部结果、alpha 差异、诊断区域和图片身份见[机器矩阵](workstation-text-rendering-results.json)。

| 场景 | P-classic20 | B0 | B1 | C |
| --- | ---: | ---: | ---: | ---: |
| 铁砧 QA | 49,631 | 48,780 | 48,311 | 0 |
| 铁砧 Long | 52,998 | 52,147 | 51,678 | 0 |
| 铁砧 Empty | 34,886 | 33,315 | 33,566 | 0 |
| 铁砧 Invalid | 38,081 | 36,510 | 36,761 | 0 |
| 砂轮 | 29,840 | 28,794 | 28,831 | 0 |
| 附魔台 | 45,284 | 44,093 | 44,093 | 0 |

B1 相对 B0 在铁砧 QA / Long 改善，在 Empty / Invalid 和砂轮退化，附魔台整帧持平。区域变化更能说明代价：

| 诊断区域 | B0 → B1：标题差异 | B0 → B1：物品栏标签差异 |
| --- | ---: | ---: |
| 铁砧各状态 | 1,763 → 2,065 | 682 → 624 |
| 砂轮 | 1,390 → 1,478 | 1,036 → 985 |
| 附魔台 | 1,038 → 1,089 | 1,190 → 1,139 |

标题都退化，物品栏标签都改善；不能用整帧减少掩盖局部退化。表中使用 raw `title` 区域，铁砧另有不同范围的 `cleanTitle`。这些诊断区域会重叠并包含背景，不能相加当作纯文字差异，也没有参与完整画面的排除计分。B0 / B1 仍保留 alpha 残差。

附魔台费用补充区域从 P 的 747 降到 B0 / B1 的 341，符文外盒区域从 14,310 降到 14,037；后者与费用盒重叠，不能据此声称未替换的符文本身改善。B0 还改变了相同 props 的书本、铁砧名称 / 费用等区域；B1 相对 P 在声明文字区域之外仍有每场景七个边界像素变化。这些结果不能全部归因于文字 callback。

六个 C 完整源 profile 和各原生 target 的独立复制显示均为完整 RGBA 零差异。这只认证固定输入、GUI5、DPR1、NVIDIA RTX 3050 / ANGLE D3D11 下的 UI target；不是默认 CSS 字体、全部 GUI、动态状态、世界合成或最终 Present 零差异。附魔台没有找到对应的完整 pre-UI PNG，因此不附加其透明清屏证明。

## 原始失败与来源

原主批尝试六场景矩阵，其中铁砧图像有效，砂轮 / 附魔台的 12 个组因私有模块 alias HTTP 500 而导入超时，主报告整体完成状态仍为 false。这些模块请求虽然在 `requestfailed` 中也标成 `ERR_ABORTED`，仍是真正的配置加载失败，不能算普通取消。

独立补批修正实验宿主 alias，先验证 125 个模块及两个 alias HTTP 200，再取得 12 张有效 holdout 图像；没有重跑或覆盖原铁砧结果。矩阵由两份 raw report 的 36 张有效图像组成，原 12 次失败单列，没有把失败改成通过。原主批另有四条 Long 源 PNG 取消；补批请求失败与页面错误均为零。它们都是辅助研究，不增加正式测试数。

两批各自前后 98 个 source pin 与 97 个 resource pin 无变化。十张已有 P 截图按完整图片比较均零差异；八次原生复制显示也完整一致，其中两个 holdout 重复。没有旧基线的配置保留为空，不用相同差异计数冒充图片身份。

## 决策与尚未解决的问题

本轮不采用 B1 默认，也不追加新的渲染 API。局部光栅再缩放与非线性 Smooth shader 的顺序、默认 8 px 字体与 atlas-rect 的差别、透明文字层和同 FBO 逐次 RGBA8 合成的舍入，都仍可能影响结果。源原点、glyph bearing、浏览器基线和光栅过程应分别验证，不依据单一截图加入逐角色偏移。

默认字体与原生画面尚未零差异；任意 Unicode、缩放、DPR / GPU、编辑状态和 Present 仍未认证。阴影单位另见[文字阴影说明](TEXT_SHADOWS.md)，本轮没有引入统一两物理像素策略。

原始报告、图片 / target SHA、区域矩形、旧 P 身份及 B1 backing 比例集中记录于机器矩阵。原点研究与失败基线探针分别保留在 `.cache/workstation-text-origin-study-01/` 和 `.cache/workstation-font-paint-probe-01/diagnostic/`；源字体与原始 PNG 不复制进发布文档。
