# 原生物品悬浮提示校准

2026-10-29，安装版 `1.26.6005.0`，Classic GUI5。本记录将 UI 定义、原生 PNG 测量、CSS 候选及未知项分开；不是整屏 pixel-perfect 验收。结构化数值和完整 SHA 见 [native-item-tooltip.json](native-item-tooltip.json)。独立审计只读原图，游戏采集和实现由主任务完成。

## 来源与采集

父任务通过原生 Alt+PrintScreen、Paint 粘贴、保存 PNG 获得三张私有截图，没有报告 JPEG 中间格式。每张为 RGBA、2568×1400：

| 截图 | SHA256 | 经原图确认的状态 |
| --- | --- | --- |
| A | `e208daf0c57fd85e462625cd567b5331968d0c99dc2f78eb0d34292cb163c409` | 钻石剑提示，含名称及“+7 攻击伤害” |
| B | `15d3a23817bd5b2da2c22aeebc2e058d9b5ca0b22931da7ab40ecfc259216581` | 同一物品提示已移动 |
| C | `c1e209c3d78ffc66b9df82aa3b380980631725e25d15fc69d57a0a7ece02a68d` | 无物品提示，可见 UI 底图 |

截图及提取的字体/纹理只在 ignored `.cache` 中供本机复核，没有随组件库分发。工具截图报告 origin(-8,-8)、2560×1400，与 PNG 尺寸不同；客户区映射未认证。下文矩形全部采用 PNG 坐标及半开区间。

安装包 `AppxManifest.xml` 已核实版本。183 个主 UI JSON 中，唯一明确 `hover_text_renderer` 定义是 `common.hover_text`：custom renderer，最大宽度参数默认 sentinel 0，layer5，`allow_clipping:false`。库存 hover control 将 collection `#hover_text` 交给它，并设 layer29；定义没有公开背景、边框、渐变、字体、阴影、padding 或定位参数。五份相关 UI 与缓存及 [Mojang 完整 v1.26.60.5 发行包](https://github.com/Mojang/bedrock-samples/releases/download/v1.26.60.5/bedrock-samples-v1.26.60.5-full.zip) parsed 对象相同。

`tooltip_default_background.png` 是灰黑 9×9、slice4，属于通用 static/dynamic Tooltip。它和键盘、通知 Tooltip，以及 HUD 手持物品说明，都不能作为库存物品紫边提示的来源。官方 item schemas 支持名称颜色与稀有度概念，但不提供本提示所有颜色值；persona/store 的 rarity 背景色不是库存名称色。

## 配对底图与颜色

稳定空背包区域 `[1350,750,1600,950]` 共 50,000 像素，A:C 与 B:C 各自严格 RGBA 零差，支持该区域内相同 PNG 坐标的 UI 配准。世界天色、物品动画、书本及鼠标所在槽的变化区域不当作精确底图。

在预先选择的无文字、完整覆盖区域，对照 C 得到：

| A 输出颜色 | C 底色 | 像素数 | 输出变化 |
| --- | --- | ---: | --- |
| 填充 `(27,12,27)` | 面板 `(198,198,198)` | 1,250 | 无 |
| 同上 | 槽底 `(139,139,139)` | 4,580 | 无 |
| 同上 | 白边 `(255,255,255)` | 240 | 无 |
| 同上 | 深灰边 `(55,55,55)` | 180 | 无 |
| 紫边 `(44,8,99)` | 面板 `(198,198,198)` | 1,290 | 无 |
| 同上 | 槽底 `(139,139,139)` | 300 | 无 |
| 同上 | 白边 `(255,255,255)` | 20 | 无 |

因此，这个样本支持 **渲染等效不透明** 的 CSS 候选：填充 `#1b0c1b`、平色紫边 `#2c0863`。不能据此声称已恢复引擎内部 shader RGBA。极近不透明的浮点颜色、混合与量化仍不能唯一辨认；但固定前景的 `240/255` 透明度无法在这四种底色上产生同一输出，不应照搬 Java 风格 alpha 常量。

A 顶部 250 像素、底部 250 像素、右侧稳定段 115 像素均严格为 `(44,8,99)`，没有该状态的纵向紫边渐变证据。角和边缘另有部分覆盖色，不将它们误作整条边框的 gradient。

独立 QA 从原图重新选取 A 独有、且 B:C 相等的稳定底区，也确认填充在 139/198/55/255 底色上不变，紫边在 198/139/55 底色上不变。该选择与上表探针不同，结论一致；其 ignored 原始记录为 `.cache/tooltip-native/independent/tooltip-independent-audit.json`。

## 外轮廓候选

A 的 exact 填充/紫边颜色 mask bounds 为 `[1244,987,1533,1127]`，B 为 `[1267,1012,1556,1152]`。包含部分覆盖边的 A painted bounds 候选是 `[1243,987,1534,1127]`，不可将 exact-color bounds 与 painted bounds 混为一个。

以 A nominal origin `(1243,987)`、每 5 个物理像素为 1 game pixel，可表达为一个 **58×28 game 的观察轮廓候选**：

| 逻辑 y 区间 | 逻辑 x 区间 |
| --- | --- |
| `[0,1)` | `[2,55)` |
| `[1,2)` | `[1,56)` |
| `[2,3)` | `[0,57)` |
| `[3,25)` | `[0,58)` |
| `[25,26)` | `[1,58)` |
| `[26,27)` | `[2,57)` |
| `[27,28)` | `[3,56)` |

另一位 QA 在读取上述期望前从原图 row spans 得到相同结果。可用 JSON 中的 step polygon 作为首个 CSS 几何候选；它不是简单对称 radius2，也不证明不对称部分来自某种原生 drop shadow。样本宽高由实际内容决定，不应硬编码所有 Tooltip 为 58×28。左右仍有约 1 物理列的混合覆盖，CSS clip-path 的采样未被认证为原生零差。

JSON 也记录了紫边的 block-center 区间：顶行逻辑 y1 为 `[2,55)`；y2/y3 的右角分别占 `[54,56)`、`[55,57)`；中段为左 `[1,2)`、右 `[56,57)`；底部 y24/y25 的左角分别占 `[1,3)`、`[2,4)`，y26 为 `[3,56)`。它可帮助构造 outer fill、purple outer、inner fill 三层候选，不能当作普通统一 border-radius 或全像素 RGBA oracle。

## 文字、行距与阴影

| 测量 | A 的 PNG 像素 |
| --- | --- |
| 名称全部非背景 ink | `[1268,1012,1394,1052]` |
| 名称满白 ink | `[1269,1012,1393,1052]`，1,020 像素，RGB `(255,255,255)` |
| 攻击行全部非背景 ink | `[1270,1062,1504,1102]` |
| 攻击行满蓝 ink | `[1272,1062,1503,1102]`，1,675 像素，RGB `(68,127,255)` |

两行 ink 高度均 40px，顶部推进 50px，即 GUI5 下 ink8game、推进10game。GUI2 的 `line-height:20px`、名称额外 margin0 是合理候选，但前提是字体具有相应 baseline/bearing。它不是独立恢复的 font-size。

nominal 外轮廓到名称 ink top/left 约 5game，包含边框、字形 bearing、linebox ascent 及采样；不能直接写成“原版 padding5game”。实际 padding 和自然宽度需要选定字形后再分离。

将满白 mask 平移 `(+5,+5)` 的探针中，818 像素落回未变的填充色；名称区没有稳定 `#3f3f3f` 灰色平台。这支持该样本未见标准 `+1game` 灰色文字阴影，`text-shadow:none` 可作为此状态候选。它不证明所有字体渲染都没有额外 shading；文字边缘有部分覆盖和小幅颜色差，不能把它们全部简化成硬像素。

后续 GUI4/5 对照已确认已测字符的基础 Unicode 位图设计，早期2.5×双线性模型失败不能用于排除该来源。`BitmapText` 可按原字图与显式 metrics 重建，并通过 `item.tooltipTextRenderer` 接入；实际字体 alias、材质分支及最终覆盖率仍未认证。详见 [NATIVE_BITMAP_FONT_QA.md](NATIVE_BITMAP_FONT_QA.md)。开源 Fusion 与 HBUI NotoSC 的相关字形存在稳定拓扑差异，仍不作为原版字形。

## A/B 位移及严格差异

A→B 的 exact fill、purple、满白、满蓝 mask 均按 `(+23,+25)` PNG 像素平移，集合对称差为 0。报告的工具 hover 点变化是 `(+23,+24)`；这 1px 差异连同未认证的客户区映射，禁止将其写成精确鼠标锚点或源取整算法。

| 比较范围 | 严格差异 |
| --- | --- |
| 四种 exact 主颜色 mask | 各 0 像素 |
| 内部 `[1260,1007,1518,1107]` 的 25,800 像素 | 1,112 像素；最大通道差 1 |
| 包含透明角及周围底图的 291×140 矩形 | 2,087 像素；最大通道差 229 |

内部差异主要是部分覆盖颜色，外围还包括不同底图。没有增加容差抹去这些差异，也没有把 mask 零差写成完整 Tooltip RGBA 零差。

## 最窄实现与验收范围

当前 `src/inventory.css` 使用上述填充色及三层阶梯轮廓、20px 行推进、无额外名称 margin 和默认文字阴影。padding8px 为明确的 Web 候选。独立导入 CSS 的测试发现 content-box 会令116×56指定尺寸外扩为132×72，已将组件自身设为 border-box，避免依赖宿主 reset。

`tests/item-tooltip-fidelity.spec.ts` 使用独立从原图记录的逐行区间作为 oracle，不读取生产 CSS 或从实现生成期望。116×56 完整矩形的6,496像素 /25,984通道与**硬边候选**零差，包含四角外底色；该测试不包含文字，也不把原生部分覆盖边缘转化为零差。真实展示页的长名称和两行 lore 已检查换行及裁切。

`ItemSlot` 的鼠标进入和槽内移动更新提示位置；键盘焦点及鼠标离开后的焦点恢复使用槽锚点，Escape 在新 hover 前保持关闭。CSS光标偏移(+24,-24)、视口8px避让是 Web 配置，不是提取的原生定位算法。耐久信息继续用于槽的可访问名称及 meter，但不会自动生成 Tooltip 正文；正文只接受名称及调用方 lore。

1. 保留独立 ItemTooltip 视觉配置；通用 Tooltip 继续使用自己的原图。
2. 以测得的平色、不透明填充和紫边替换未证实的透明/渐变常量；使用观察到的阶梯角作为待测几何候选。
3. 用 10game 行推进作为目标。padding、font-size、自然宽度须与字形 bearing 分开验证，未知时保持标注。
4. 内容由宿主提供，不自动生成原版未声明的 durability、高级信息、稀有度规则或颜色映射。
5. 光标跟随、focus fallback、屏幕边缘 clamp 可以是明示的 Web 行为；本次没有认证对应原生定位算法。
6. 浏览器回归分别检查核心平色、边框/角、文本和交互；私有截图缺失时应区分可选本机证据与公开源码检查。本轮只认证上述 A/B/C 局部采样，不扩张为所有物品、所有语言、所有 tooltip mode 或整屏像素一致。
